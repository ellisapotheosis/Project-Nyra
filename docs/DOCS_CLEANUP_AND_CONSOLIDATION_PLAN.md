# 175-IQ Docs Cleanup & Consolidation Plan (v3)

## 🚨 The Problem: Documentation Sprawl & Duplicity

Currently, the `/docs` directory has accumulated significant complexity. There are redundant folders (e.g., `/docs/ops/` vs. `/docs/operations/`, `/docs/network/` vs `/docs/networking/` vs. root level network topologies), scattered application spec documents, and multiple sync-conflict files (e.g., `*.sync-conflict-*.md`) generated by file sync issues.

This plan establishes a **pristine, highly structured, 4-tier taxonomy** that consolidates all files, eliminates duplicates, and organizes every service/app documentation file into its own designated home.

---

## 🏛️ The Target Taxonomy

We will clean up and consolidate the `/docs` directory into four logical master folders:

```
docs/
├── apps/               # 1. User interfaces, landers, CRM, workflows (gated or public)
│   ├── projectnyra/    # app.projectnyra.com (Broker command center webapp)
│   ├── ratehunter/     # ratehunter.net (Borrower landing page, borrower-nexus)
│   ├── twentycrm/      # Twenty CRM core, CRM API, CRM UI guides
│   ├── activepieces/   # Activepieces workflow engine, embedded flows
│   ├── n8n/            # n8n drip campaign config & fallback policies
│   ├── nexus-ui/       # Nexus UI control panel, nexus router schema
│   ├── openmemory/     # OpenMemory MCP & OpenMemory UI
│   └── gastown/        # Gastown Operator Workspace & clawteam dashboards
│
├── infrastructure/     # 2. System topology, host layouts, security, and operations
│   ├── networking/     # Canonical Network Map, Tailscale, Cloudflare Access & DNS
│   ├── secrets/        # Infisical setups, token scopes, rotating guides
│   ├── observability/  # Prometheus, Grafana, Loki, cAdvisor, and logging specs
│   └── hosts/          # Hardware/host specifications & recovery runbooks
│
├── architecture/       # 3. High-level specifications and decisions
│   ├── adr/            # Architectural Decision Records (ADRs)
│   └── specs/          # Pure backend specs (e.g., Quote Engine, Rate API)
│
└── archive/            # 4. Retired documentation, historical guides, and logs
```

### 4. Sweep and Safely Quarantine Sync Conflicts & Logs to `/docs/archive/`

We will NEVER delete historical context, but we must quarantine clutter and sync-conflict files:

1.  Create `docs/archive/sync-conflicts/`.
2.  Find all files matching `*sync-conflict*` recursively in the repo (or just under `/docs/` and `/infra/`) and move them into this directory to preserve their history without cluttering your core directory tree.
3.  Move old templates and historical handoff prompts (like `AGENT_HANDOFF_PROMPT_2026-05-19.md`, `AGENT_RELEASE_HANDOFF.md`) to `/docs/archive/handoffs/`.
